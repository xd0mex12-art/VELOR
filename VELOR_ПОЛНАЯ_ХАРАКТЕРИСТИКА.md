# VELOR AI — полная характеристика приложения

Документ-контекст для языковой модели. Состояние на 5 сентября 2026 года,
ветка `fix/universal-client-bot-persona`, 61 коммит.
Все цифры ниже посчитаны по коду, а не по памяти.

---

## 0. В одном абзаце

VELOR AI — мультитенантный SaaS-ассистент для владельца малого и среднего
бизнеса. Один сервер обслуживает произвольное число компаний (`business_id`
в каждой таблице и почти в каждой функции). Продукт принимает данные бизнеса
из разговоров, файлов и внешних сервисов, превращает их в структурированную
«память бизнеса», сам замечает проблемы и возможности, готовит действия
и — в рамках выданных ему полномочий — выполняет их. Общение с клиентами
идёт через Telegram-бота и Instagram Direct, работа владельца — через
веб-кабинет из 45 страниц. Язык интерфейса и кода — русский.

**Не CRM и не дашборд.** Формулировка, которой держится весь продукт:
ни одного вывода без цифры и ни одной цифры без источника.

## 2. Стек

- **Backend:** Python 3.12, FastAPI 0.115, uvicorn. Без ORM — прямой SQL.
- **База:** SQLite локально; PostgreSQL (Supabase) в проде через `DATABASE_URL`,
  драйвер `psycopg[binary]` + пул. `database.py` абстрагирует оба варианта
  и **отказывается стартовать** при `APP_ENV=production` без Postgres.
- **Бот:** `python-telegram-bot` 21.6. Два режима запуска — long polling
  отдельным процессом (`bot.py`) и webhook внутри веб-сервиса
  (`POST /api/tg/webhook/{token}`). Общая логика вынесена в `botcore.py`,
  чтобы поведение совпадало.
- **ИИ:** Google Gemini (основной), GigaChat/Сбер (резерв с автооткатом),
  Anthropic Claude (`anthropic==0.116.0`, исторический первый провайдер).
- **Документы:** pypdf, python-docx, openpyxl, reportlab (PDF с кириллицей).
- **Крипто:** `cryptography` — шифрование чужих API-ключей (`secretbox.py`).
- **Фронтенд:** ванильные HTML/CSS/JS. **Ни одного фреймворка, ни сборки,
  ни npm.** Страницы — самостоятельные документы, общая оболочка через
  `nav.js` и cross-document View Transitions.
- **Деплой:** Docker Compose (web + bot + nginx + certbot + backup) либо
  Render (`render.yaml`), Procfile для heroku-подобных.

### Карта модулей — что каждый решает

| Модуль | Ответственность |
|---|---|
| `database.py` | Всё чтение/запись. Каждая функция принимает `business_id` — это и есть мультитенантность. Аддитивные миграции при старте. |
| `server.py` | 185 эндпоинтов, статика, JWT-гейты, фоновый воркер синхронизации. |
| `ai.py` | Выбор провайдера, автооткат Gemini → GigaChat, единый интерфейс запроса. |
| `prompt_engine.py` | «Мозг за мозгом». Владелец не пишет промпты — пишет как живому сотруднику. Движок определяет задачу, подбирает **профессию** (маркетолог, продавец, финансист) и собирает системный промпт. |
| `context_engine.py` | Перед каждым запросом к LLM автособирает контекст: компания, знания, RAG по документам, память, CRM, финансы, конкретный клиент. Работает поверх Prompt Engine, с откатом. |
| `understanding.py` | Три шага, каждый может обойтись без следующего: ЧТЕНИЕ (PDF/DOCX/TXT/CSV/XLSX) → РАЗБОР (тип, цифры, предложенное действие) → РЕШЕНИЕ (уверенность, можно ли без человека). Два разборщика: модель и правила. |
| `intake.py` | Единое окно входящих. Одна дверь для заметок, файлов, сообщений бота и будущих источников; правила «что принимаем / сколько / не дубль ли» описаны один раз. |
| `entities.py` | Реестр 13 видов бизнес-сущностей, описанных **данными**, а не кодом: company, service, product, employee, supplier, rule, client, lead, order, expense, income, goal, document. Группы: company/offer/people/rules/goals/money/docs. |
| `graph.py` | Связи: кто с кем и через что. Отвечает на «хочу повторить прошлый заказ» и «сколько мы платим Петровой». |
| `director.py` | AI Director: «что происходит с бизнесом». Каждая строка собрана из конкретных записей с указанием периода, числа операций и базы сравнения. |
| `initiatives.py` | VELOR замечает сам, по расписанию: находки, а не отчёты. Каждая находка несёт `evidence` — список id записей, на которых она построена (Evidence Chain). |
| `signals.py` | Реактивное ядро: изменение данных автоматически влияет на другие модули — детерминированные инсайты в ленту, флаги `dirty` для пересборки Директора/брифинга, прогноз. |
| `qualify.py` | Оценка возможности. **Не балл**, а разбор: дорогая или горячая, наша или чужая, что делать сейчас. |
| `leads.py` | Лид как коммерческая возможность — не человек и не заявка, а то, что между ними: статус, история, причина проигрыша. |
| `followup.py` | Удержание возможности, а не напоминание о себе. Пишет только при конкретном незакрытом обязательстве. |
| `actions.py` | Граница «ИИ что-то делает» / «ИИ действует в рамках полномочий». Единый журнал и единый вопрос «можно ли?» вместо четырёх разных. |
| `sales.py` | Продавец, который не умеет выдумывать: ни одной цифры, которой нет в памяти бизнеса. |
| `outputs.py` | То, что владелец уносит наружу: отчёты, документы, файлы. |
| `exporters.py` | CSV / XLSX / PDF. Два слоя: `dataset()` — что выгружаем, writer'ы — как упаковать. |
| `finance_import.py` | Выписка банка → операции. Конвейер: источник → нормализованные операции → категоризатор → сохранение. |
| `connections.py` | Одна дверь во внешний мир: подключено ли, когда обновлялось, что видит, почему не работает — одинаково для всех сервисов. |
| `trial.py` | Единственное место логики пробного периода. Никаких ручных проверок дат по проекту. |
| `plans.py` | Единственный источник истины по тарифам. |
| `billing.py` | Деньги. Подписку включает только подтверждённая оплата. |
| `identity.py` | Owner Identity: триал привязан к личности владельца, а не к боту. |
| `auth.py` | JWT без внешних зависимостей: access HS256 + отзываемый refresh (в базе только хеш). |
| `ratelimit.py` | Защита от перебора паролей и спама регистраций, в памяти. |
| `safeurl.py` | Анти-SSRF: сервер ходит только по http(s) и только на публичные имена. |
| `secretbox.py` | Ключи чужих сервисов нельзя хешировать (их читают на каждую синхронизацию) — значит шифруем. |
| `errorlog.py` | Разбор `errors.log` для журнала ошибок в кабинете. |
| `instagram.py` | Instagram API with Instagram Login (без страницы Facebook), graph.instagram.com. |
| `botcore.py` | Ядро обработки входящего сообщения, не зависящее от Telegram-фреймворка. |

## 6. ИИ-слой

**Провайдеры и откат.** `ai.py` пробует основного, при недоступности
(нет ключа, нет баланса, ошибка) переключается на резервного. Ключи:
`GEMINI_API_KEY` (+ `GEMINI_MODEL`, `GEMINI_BASE_URL` — можно указать
реселлера с OpenAI-совместимым API), `GIGACHAT_AUTH_KEY`, `ANTHROPIC_API_KEY`.

**Заточка под бизнес — не дообучение, а RAG-в-контексте.** Знания компании
инжектятся в промпт: `context_engine.py` собирает компанию, память, документы,
CRM, финансы и текущего клиента; `prompt_engine.py` подбирает «профессию»
под задачу. Отдельной или дообученной модели нет и не планируется.

**Продавец не выдумывает.** `sales.py` физически не даёт модели назвать цену,
которой нет в памяти бизнеса: выдуманная цена дороже упущенной сделки —
по ней клиент придёт, а владелец будет объясняться.

**Ограничение частоты:** `ASK_MAX=30` запросов в минуту на ключ.

## 7. Автономность — самая своеобразная часть продукта

14 полномочий в `actions.REGISTRY`, у каждого: название, объяснение
человеческим языком («что это значит»), группа (продажи / данные /
операции / финансы), уровень риска, режим по умолчанию и **потолок**.

Три режима: `deny` (запрещено) → `approval` (готовит, ждёт подтверждения)
→ `auto` (делает само).

Примеры с их настройками:

| Полномочие | Риск | По умолчанию | Потолок |
|---|---|---|---|
| Отвечать клиентам | high | auto | auto |
| Оценивать возможности | low | auto | auto |
| Писать клиенту первым | high | **approval** | auto |
| Изменять подтверждённые данные | high | **approval** | **approval** |
| Записывать расходы и доходы | high | **approval** | **approval** |

Потолок `approval` означает: **владелец не может разрешить это делать
автоматически**, даже если захочет. Деньги и подтверждённые им факты
VELOR не трогает без подтверждения — это встроено, а не настраивается.

Всё сделанное пишется в `actions` с полями `before` / `after` / `based_on` /
`reason` — журнал, а не лог.

## 8. Тарифы, триал, оплата

**Каталог (`plans.py`, единственный источник истины):**

| | START | BUSINESS *(популярный)* | NETWORK |
|---|---|---|---|
| Цена | 4 900 ₽/мес | 9 900 ₽/мес | 19 900 ₽/мес |
| Базовая аналитика, AI Director | ✓ | ✓ | ✓ |
| Автовыявление проблем | — | ✓ | ✓ |
| Расширенная аналитика | — | ✓ | ✓ |
| Несколько направлений | — | — | *готовится* |
| Приоритетная поддержка | — | — | ✓ |
| Источники / история / сообщения | 3 · 90 дн · 2 000 | 10 · 365 дн · 10 000 | ∞ · 1095 дн · 50 000 |

**VELOR SETUP** — 15 000 ₽ разово: «Дайте нам данные — мы настроим VELOR
под ваш бизнес» (профиль, цели, источники, AI Director, знания, Telegram,
первичная аналитика, первый брифинг).

**Founder Pilot** — не тариф, а флаг: setup бесплатно, первый месяц 4 900,
дальше 9 900, тариф business.

**Триал:** 14 дней полного доступа (BUSINESS). Отсчёт только на сервере.
Привязан к личности владельца, а не к боту, — новый бот не даёт нового триала.

**Правило после окончания, на котором держится продукт:** данные остаются
видимыми, останавливаются операции. Поэтому в коде разведены два вопроса:
`plan_entitlements()` спрашивает тариф (пускать ли к разделу),
`entitlements()` — доступно ли прямо сейчас (с учётом срока). Два разных
HTTP-кода: **402** — истёк срок, **403** — не тот тариф.

**Оплата (ЮKassa):**
```
выбор тарифа → payment(pending) → страница ЮKassa → оплата
  → webhook → ПЕРЕПРОВЕРКА через API ЮKassa нашими ключами
  → сверка суммы → SQL-замок → подписка активна
```
Телу вебхука не верим (ЮKassa его не подписывает) — из него берём только id.
Возврат пользователя на сайт **ничего не активирует**. Цену считает сервер.
Идемпотентность — условие внутри самого `UPDATE`, а не `SELECT` перед ним.

## 9. Безопасность

- Пароли — PBKDF2. Сессии — JWT: access 30 мин + отзываемый refresh 30 дней
  (в базе хеш).
- Rate limit: вход 8 промахов / 15 мин, регистрация 5 / час, ИИ 30 / мин.
- В `production` сервер **не стартует** с дефолтными кредами владельца
  и без Postgres.
- Ключи внешних сервисов шифруются (`SECRET_KEY`), не хешируются.
- Анти-SSRF на каждом месте, где сервер идёт по введённому адресу.
- Мультитенантность проверяется тестами: чужой платёж — 404, чужие данные
  не видны, `business_id` в каждом запросе.
- 152-ФЗ: есть `consent.html` и `privacy.html`; данные граждан РФ по закону
  должны храниться в России — сейчас сервер во Франкфурте, вопрос открыт.

## 10. Фронтенд и дизайн-система

**45 страниц**, крупнейшие: `dashboard.html` (1 404), `inbox.html` (1 335),
`knowledge.html` (1 000), `leads.html` (933).

**Навигация — 6 разделов** (`nav.js`), внутри каждого свои подпункты:
Брифинг · Входящие · Реестр · Работа · Знание · Ещё.

**Стиль Dala:** почти чёрный фон `--void:#08080b`, шрифт Inter, акцент
ирис `--iris:#8052ff`, бирюза `--verdant`, янтарь `--saffron`, коралл `--coral`.
Все токены — только в `web/velor.css`, который подключается **после**
инлайновых стилей и потому перебивает локальные `:root`. В стилях страниц
хардкодить цвета запрещено — только `var(--…)`.

**Живое поле (Living Intelligence Field)** — фирменная деталь: три огромных
светящихся объёма за интерфейсом, у каждого свой размер, траектория, период
и деформация; периоды — взаимно простые числа, поэтому композиция не
повторяется. Четыре базовых состояния различаются **формой**, а не цветом
(ожидание — рассеяны, норма — широко, риск — сжаты, возможность —
вытянуты направленно). Поверх — бизнес-сигналы: янтарный узел неотвеченных
лидов. Только CSS, только `transform`/`opacity`, без Canvas и WebGL.
Контраст текста поверх поля считается численно в `tests/t_design.py`.

**VELOR CORE** — знак присутствия: дышащие нити, реагирующие на состояния
(`idle` / `thinking` / `generating` / `analyzing` / `error` + золотой импульс
инсайта) через `window.VELOR_CORE.setState`.

Дизайн-система описана в `VELOR_DESIGN_SYSTEM.md` (20 разделов), карта
продукта — в `PRODUCT_MAP.md` по схеме
ПОТРЕБНОСТЬ → РАЗДЕЛ → СТРАНИЦА → СУЩНОСТЬ → ДЕЙСТВИЕ.

## 12. Тесты

Особенности, которые важно сохранять:
- Тесты написаны **утверждениями о продукте**, а не о функциях:
  «после окончания срока разделы всё равно открываются», «но связи видно».
- Дизайн проверяется численно: `t_design.py` (1 153 строки) считает контраст
  композиции по фазам анимации и WCAG-отношения.
- Проводится **мутационное тестирование самих тестов**: в код вносится
  дефект и проверяется, что проверки его ловят. Так была найдена дыра —
  снятый SQL-замок идемпотентности не ловился, пришлось добавить прямую
  проверку примитива.

## 14. Язык продукта — важно для промптов

Это не косметика, а часть спецификации. VELOR разговаривает с владельцем
по-русски, живым языком, короткими утверждениями. Правила, выдержанные
по всему коду и интерфейсу:

- **Никакого канцелярита и буллетов ради буллетов.** «Клиент спросил и не
  получил ответа» вместо «зафиксировано отсутствие реакции на запрос».
- **Каждое утверждение подкреплено источником.** Если цифру нельзя
  проверить — её не показывают.
- **Объяснение вместо термина.** У каждого полномочия в реестре есть поле
  «что это значит» на человеческом языке.
- **Честность важнее полноты.** Нереализованное помечается «ГОТОВИТСЯ»,
  а не выдаётся за работающее.
- **Комментарии в коде объясняют «почему», а не «что».** В проекте принято
  писать в комментарии причину решения и что случилось бы иначе.
- Термины: «возможность» (не «лид» в UI), «память бизнеса», «находка»
  (не «отчёт»), «полномочия» (не «настройки автономности»),
  «режим просмотра» (не «блокировка»).

## 16. Как писать промпты под этот проект

1. **Сначала аудит, потом изменения.** В проекте уже был случай трёх
   несовпадающих каталогов тарифов; любая новая подсистема сперва ищет,
   не существует ли она уже.
2. **Никаких заглушек, выдаваемых за работающее.** Если backend не
   поддерживает — не показывать как доступное.
3. **Фронтенд не система безопасности.** Любое ограничение проверяется на
   сервере и возвращает 402/403.
4. **Не ломать существующее.** Перед правкой — найти все использования;
   в конце — прогнать `python tests/run_all.py` целиком.
5. **Тесты пишутся про продукт**, а не про функции, и их самих стоит
   проверять мутацией.
6. **Стиль оставлять Dala**, токены — только из `velor.css`.
7. **Отчёт в конце**, а не «Готово»: что найдено, что изменено, что
   осталось, и особо — что требует реальных ключей для прода.
